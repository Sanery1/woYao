# 验证

## 内容完成

- 关键事实、版本、数字与来源相符，声明/观察/推断/教学例子分清。
- 默认报告导入简短，主体包含完整核心机制、相关的抽象原理与实际取舍；后层推进理解，不重讲概述。
- 必要概念在用到时解释，算例可复算，简化条件清楚；默认结尾 `oOO!` 贯通机制、收益与代价并回答起始问题，不能用标题代替内容。
- 顺着一个核心案例检查：输入是什么、每步状态如何变化、为何选择该分支、最终得到什么结果；只有流程名称或恢复策略而没有结果时，继续补齐。
- 图与正文一致；图应增加可见的状态、顺序、数量或结构差异。方案比较有适用条件和代价，重要未知明确。
- 开头有实际 Skill 版本与日期，来源能回查。标题、署名、总结名称和题数不作质量代理。

只要 Markdown 时检查正文、围栏、链接与资源即可，不需安装 Node/Python。默认报告检查与特殊用途相适应，不强行补综合综述。

## HTML、按需 PDF 与自动检查

默认 HTML 按 [html-and-diagrams.md](html-and-diagrams.md) 检查。实际查看每幅图，核对图字、箭头、颜色角色和正文含义；离线可读，窄屏不出现整页横向溢出。静态内容在禁用脚本时仍完整。理解效果以读者反馈为准。

按需 PDF 入口 `scripts/export_pdf.cjs` 使用 md-to-pdf，统一处理数学、Mermaid、本地图片、等待渲染、排版溢出和目标文件保护。实际查看每页 PDF，尤其中文、图中文字、公式末尾、长表及尾页；发现问题从 Markdown 修复重建。脚本不能证明来源支持或读者理解。

`render_knowledge.cjs` 的候选构建接口仍兼容旧调用。`check_document.py` 和 `publish_document.py` 保留为可选的历史清单校验/授权更新工具；它们不是日常 Markdown 或 PDF 导出的前置环境。历史版本按原清单核验。

## 维护者回归

HTML 入口变更先运行 `node tests/test_html.cjs`，覆盖普通 Markdown、公式、本地图片、失败无产物及已有文件保护；再用完整报告检查桌面、窄屏、目录、放大与禁用脚本阅读。此入口不启动浏览器，视觉检查单独使用宿主已有浏览器能力。

脚本变更时跑受影响的现有回归，保留公式完整、图渲染、非法资源与已有文件保护。新增默认入口要验证普通 Markdown 无品牌章节可导出、失败不产生成功产物、再次运行不覆盖用户工作。

工程通过后仍需真实报告：算法类检查算例与参数解释，框架类检查状态/恢复与实现，抽象机制类检查先修依赖和反例。优先完整报告，局部导读与模板重渲染不能证明深度阶梯有效。多宿主安装识别不等于在各宿主完成研究；实际执行与未验证范围分别记录。
