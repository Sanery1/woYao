# 输出约定

默认 `<topic>.md` 和同名 `.html`；PDF 仅在明确要求时生成。必要图片以相对路径放在报告目录内。Markdown 是唯一正文源，HTML 与 PDF 不分别维护正文；修改源后重建所需格式。用新报告目录保留已有工作。HTML 和机制图见 [html-and-diagrams.md](html-and-diagrams.md)。

## 开头信息

读取 Skill 根目录 VERSION，开头明确实际 Skill 版本与研究日期。读者、范围、软件版本和证据边界用简短文字自然交代；文档修订号、生成者和署名可选。模板示意：

```markdown
# 报告标题

- **Skill 版本：** woYao v<实际 VERSION>
- **研究日期：** YYYY-MM-DD

一句话说明本次范围、必要假设及重要证据限制。
```

保持版本真实，不改写历史文档的生成版本以通过转换。导出器接受普通 Markdown，不以文章品牌、署名或章节名判断能否排版。

## 正文与结尾

按主题和读者的理解依赖组织。重要结论就近引用真实读过的来源；文末列可回查来源及必要版本/条件。区分官方声明、自己的推断、教学数字和实际观测。

默认在参考资料前以 `## oOO!` 收束正文，用 1–3 个简短段落贯通全文：点明问题本质，解释主要方案为何有效及其收益、代价，并回到起始问题。不要只重复目录或再列一遍术语；它承担综合理解，不能只补一个标题。用户明确指定其他结构时按其要求调整。

这是默认写作约定，不是 PDF 导出门槛；转换脚本继续接受没有 `oOO!` 的普通 Markdown。宏观读后问题、词表、署名与附录按需要使用，不要求固定题数。
