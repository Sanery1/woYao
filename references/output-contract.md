# 文档契约

## 文件与版本

标准输出 `<topic>.md`、同名 `.pdf`，仅必要时加相对图片资源。使用清楚合法的主题短名，不让输入成为任意路径。Markdown 唯一源，编辑后重建 PDF。

`skill_version` 是实际安装 Skill 的发布版本，必须读取根目录 `VERSION`；`document_version` 是文章修订号；`subject_versions` 是研究对象版本。规范版本仅供维护，不作为报告的工具版本。正文示例中的 `<VERSION>` 必须替换为读取到的值：

```markdown
# 文档标题

*一句话说明范围*

<!-- woyao:metadata -->
- **Skill 版本：** woYao v<VERSION>
- **研究日期：** YYYY-MM-DD
- **读者：** 本次目标读者
- **证据范围：** 实际阅读的来源与限制
- **研究对象版本：** 实际版本；无版本的理论可省略
- **文档版本：** 1.0
- **生成者：** woYao skill by saneryi
- **研究限制：** 仅必要时填写，例如未联网或未复跑实验
<!-- /woyao:metadata -->
```

必需字段为 Skill 版本、研究日期、读者、证据范围、文档版本、生成者，每项独占一行。署名不证明实验/自动化完成。不把示例日期、JEV 版本或样稿状态硬编码。可加 YAML frontmatter，但正文元信息仍可读。Skill 版本在第一个 H2 之前且仅出现一个版本声明行，Markdown 与 PDF 同源显示。构建器要求它等于本机 VERSION，并把版本记入清单；验证历史产物时与当时清单比对，不要求等于今天安装的版本。重建旧文章须更新版本声明，旧文件不自动改写。

## 读后核心问题

正文稳定后提炼通常 4–6 个宏观问题，短文/reference 可以更少。候选方向为定位、价值、机制、替代路线、适用与选择，按主题合并调整，不固定六道问卷。

让未读文章的人也能理解问什么，聚焦能解释/判断什么。阈值、算式数值、单个字段和实验探针留在相关章节。建立“问题 → 正文解答段落”的内部对应；没有答案就补证/补写或改题。

BM25 可问怎样排序、与向量检索何异、何时有效；LangGraph 可问节点与状态如何协同、恢复为何需持久化、何时值得用。不照搬 JEV 五问措辞。

## 固定收尾

```markdown
## 读完以后，你应该能回答这些问题

1. 主题级问题？

## oOO!

准确大白话点破本质，恰当时与熟悉方案对比，简明讲收益与代价。

## 参考资料与证据级别

[来源标题](https://example.org/original) — 证据性质、日期/版本、支持范围与限制。
```

最后两个 H2 精确为 `oOO!`、`参考资料与证据级别`。附录、词表与练习在前。`oOO!` 通常 1–3 个短段落，不引新事实、不写空泛感言或绝对性能断言。问题放其前，不另做整页试卷。

用户明确改结构时按请求；检查脚本 `--relaxed` 只跳过默认结构规则，Skill 版本、资源和构建一致性仍检查。
