# 五种写作目的

应用所选模式细则，共享证据与输出契约；显式用户要求优先。

## general（仅有主题时默认）

目标是开发者能理解、复述并选型。按先修依赖组织：真实问题/直觉 → 最小正确全貌 → 贯穿案例 → 必要机制 → 有条件比较 → 应用、失效与验证。可穿插，不固定章节数。

核心概念经历定义、动机、例子、严格解释。首次展开缩写，先解释再使用。公式、代码、状态决定因果就深入，无需生成完整应用。比较解释差异为何产生，不只列优缺点。正文与图共同展示输入、中间过程和输出；合成例子标识清楚。

## tutorial

在引导实践中学会。给学习成果、环境/版本和能完成的小成果；按顺序安排动作，每阶段有可观察结果，解释够完成当前步骤，提供常见错误及恢复。命令未运行则标明，不伪造成功日志。读后问题聚焦实践背后的核心认识。

## how-to

完成明确任务。开头给目标、适用条件和前置要求，随后给必要步骤、场景分支、结果验证和可行恢复措施。假定已有基础，长背景放必要位置或引用。文档中的操作说明不等于授权本次执行外部写入。

## reference

快速准确查阅。按概念、API、参数、类型、默认值、返回值、错误、版本和兼容组织，使用可查标题/表格。默认值与签名必须有版本/来源。未公开信息写未知，不补造字段；短例子说明边界，不强行长叙事。读后问题可精简为理解与正确使用契约的宏观问题。

## explanation

理解原因、思想和取舍。围绕动机、因果机制、假设、替代解释与局限，用反例及必要例子说明设计。代码仅辅助，不退化成操作手册。

各模式 `oOO!` 服务当前读者目标，内容来自正文。专用模式的深度体现在所需证据和准确性，不强行塞综合综述。

## 范围与完成条件

模式决定文档服务什么任务；系统学习/快速决定覆盖范围；Markdown/PDF 决定交付形式。三者独立。自然语言优先识别目的，显式模式优先于自动判断。

| 模式 | 检查可观察结果 |
| --- | --- |
| general | 有正确的输入到输出解释、例子与适用判断 |
| tutorial | 步骤连贯，前置条件明确，每阶段有可观察结果；运行与未运行分清 |
| how-to | 可完成指定任务，包含结果验证及相关失败处理 |
| reference | 参数、默认值、签名和错误有版本依据，标题便于查阅 |
| explanation | 回答为什么，说明因果、假设、反例或取舍 |

快速范围不主动扩展旁支主题；系统学习也在核心问题得到回答后停止。范围裁剪后仍保留当前模式必要的完成条件。显式“只要 Markdown”才取消默认 PDF。
