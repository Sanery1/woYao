# 写作与教学

## 默认：完整学习报告

按本次读者区分已知、必要先修和旁支。少量段落交代问题、输入输出与价值后，尽快进入机制；入门只是起点，核心和进阶构成主体。

| 层次 | 完成信号 |
| --- | --- |
| 简短入门 | 知道正在解决什么问题，能进入后文 |
| 核心机制 | 必要概念在例子中有具体作用，关键步骤与结果能复述或复算 |
| 进阶抽象 | 从例子推出规律，说明假设、参数影响、复杂情况或反例 |
| 工程判断 | 用机制解释真实实现与方案差异，给适用条件和验证办法 |

这是理解顺序，不是固定四章。每节承接已得到的认识，回答一个新增问题。由具体上升到公式、模型或设计原则时，交代新抽象对应例子中的什么、为什么需要；再用变式或边界检验。相关推导与取舍在报告内真正展开，不只列作外链。

术语按理解依赖出场：先交代当前步骤需要解决的问题，再引入承担该作用的概念。判断一个术语是否现在必要：删掉它是否妨碍解释眼前这一步？不妨碍就延后。缩写展开后仍解释含义；比如数某词在一篇文档中出现几次后说明这就是 TF，再讲它如何进入评分。

核心机制用一个具体实例走完：输入 → 关键中间状态或计算量 → 分支选择及理由 → 可观察结果，最后回答起始问题。理论综述可用相互联系的例子；教学重建、框架能力和应用补充分别说清。

例如，恢复报告只说“按策略重试”尚未闭环；应继续展示保存了哪次调用、恢复读取了什么、为何重跑或停下，以及如何确认最终结果。若外部写入是否成功无法判定，就以明确的待核验状态结束，解释应用需要什么证据，不能替框架虚构自动核验。算法报告则给出具体输入、关键中间量和最终得分，再用一个变式检验规律。

按理解依赖区分核心主线、能力扩展和工程落地，用有意义的二、三级标题体现层级；短报告无需机械分组。关键解释保持展开，每节突出影响理解或判断的结论。开头保留版本、日期和简短证据说明；详细研究范围归到文末，局部限制只在改变当前结论时说明。压缩重复定义、生活类比、开场价值宣讲和逐段总结，保留决定因果的解释。静态报告不强制逐段问答。读者反馈应修订具体卡点；内容自检不是理解效果证明。

## 用户明确指定特殊用途时

兼容旧模式名，按目的调整正文；默认报告本来就可以包含必要解释、例子与操作，不用先让用户选菜单。

- **tutorial**：学习成果、环境/版本、顺序动作与阶段结果，说明常见错误；执行与示例分清。
- **how-to**：目标、适用条件、必要步骤、验证与相关失败处理，背景就近补充。
- **reference**：准确的参数、签名、默认值、错误与版本来源；按查阅组织，短例子解释边界。
- **explanation**：聚焦明确的为什么，展开因果、假设、反例与取舍；代码辅助解释。

“快速”聚焦当前问题和必要机制；“系统学习”覆盖关键机制、进阶解释与判断。显式用户目的和篇幅优先，不机械填齐所有层次或章节。
