# 写作规则

保留具体过程、完整解释链与逐层深入；用 [好坏对照 G1–G8](../examples/style-pairs.md) 检查执行效果。规则编号是引用入口，其他文件按编号引用。

- **T1 场景开头。** A/B 档开头≤3段，建立处境、问题与读后能力，先让读者知道为什么要关心。C 档可一句话定位并给全景。〔G1〕
- **T2 术语就近建立。** 首次使用必要术语加粗，在同句或下一句说明含义与当前作用，再用它解释过程；术语先用后定义会给检查 WARN。标题内命名不算已讲过。〔G2〕
- **T3 稳定例子。** 沿同一组对象/一次请求/一条论证推进，进阶只改变明确条件；比较候选也使用同一业务约束。〔G3〕
- **T4 解释链。** 每个核心机制交代输入、发生了什么、为什么这样设计、结果、成立条件与代价，再把机制连回总问题。保留旧版的关键推导，不能用规则列表代替正文。〔G4〕
- **T5 公式对应对象。** 先说要算的量/表达的关系，定义符号与假设，随即用贯穿例子代入并解释结果；理论公式可用具体对象、反例或符号变式，不强造数字。计算值按 evidence 的 calc 约定。〔G4〕
- **T6 节间有推进。** 开头说明这一节新增的问题，结尾交代所得认识如何被下一节使用；不重复整节摘要。〔G4、G8〕
- **T7 集中证据边界。** 每节优先只保留一句会改变本节判断的限制，其余归入末尾证据边界。条件直接限定结论，必要安全/正确性条件保留在使用处。〔G5〕
- **T8 关键断言带标签。** 标签和台账以 [evidence](evidence.md) 为唯一规范；数字、比较、版本行为和新结论就近标记并引用。〔G5〕
- **T9 计算可回放。** 相关段落前标 calc 名称，脚本/.out 按 evidence 约定保存，正文逐项核对输出。〔G4、G5〕
- **T10 因果用段落。** 列表用于并列项或操作顺序，推理写连贯文字，让读者无需自己拼接步骤。〔G6〕
- **T11 表后解释。** 表后回答“这个差别说明什么/因此怎么选”，避免只有数据没有判断。〔G4〕
- **T12 删除空话。** 删除“值得注意的是、众所周知、本文将、总的来说、让我们来看看、不难发现”等预告，直接推进认识。〔G7〕
- **T13 回到开头。** 用 `## 回到开头` 的≤3段将已讲机制用于起始处境，说明如今如何理解或行动。〔G8〕
- **T14 预算取舍。** 先删旁支，再删重复铺垫，再合并相近节，最后压缩进阶；核心 T4 解释链保留。删去的旁支记 map 并交付。〔G7〕

## 档位与目的

| | A 不写代码 | B 会编程 | C 从业者 |
| --- | --- | --- | --- |
| 对象 | 业务/生活过程，类比就近说明对应边界 | 请求、数据结构、可运行片段 | 真实配置、固定版本源码 |
| 公式 | 先用文字讲关系，必要公式可放补充细节 | 按 T5 给算例 | 重点推导与变体，省略已知基础 |
| 代码 | 默认不用 | 最小片段，注明运行状态 | 关键实现与出处 |
| 重心 | 机制与可判断结果 | 机制、工程取舍 | 内部实现、边界、替代设计 |

目的决定骨架，见 planning；选型以需求—候选—对比—推荐—验证推进，教程以可运行阶段结果推进。逐节写入 report，每节对照它负责的目标题再继续；正文保留解释链与必要深入，不以满足题目关键词替代完整理解。
