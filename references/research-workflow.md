# 技术主题研究

## 问题地图

确定对象、含义、版本/时间范围、读者目的与来源。维护两层：内部研究问题地图深入机制、参数、公式、状态、实现、实验与未知，记录核心/先修/延伸；对外学习成果则是少量主题级理解和决策问题，不直接复制细节清单。

| 类型 | 高价值研究方向 |
| --- | --- |
| 模型/学习方法 | 范式、任务与输入输出、公开架构、训练与推理、规模/资源、质量证据、替代路线、部署与未知 |
| 算法/检索 | 假设、步骤、公式与符号、逐步算例、复杂度、参数敏感性、实现差异、失败条件、基线 |
| 框架/运行时 | 抽象、控制流/数据流、状态、调度、并发、持久化/恢复、副作用、版本、替代编排 |
| 系统/分布式设计 | 负载与需求、正确性不变量、时序、故障与恢复、瓶颈、成本、验证与替代设计 |
| 协议/API/工具 | 请求响应、契约、状态机、权限边界、兼容、错误语义、最小用法与版本迁移 |
| 理论/概念 | 定义边界、动机、流派、假设、因果、反例、可检验命题、代表性证据 |

这些是候选，不是必填表。跨类型主题融合相关维度；不为未知闭源系统虚构结构。

## 搜索回路

1. 首轮读原始论文、规范、官方文档或源码，核实术语和版本；搜索摘要只作导航。
2. 从新证据提出遗漏问题：不回答会不会误解机制，是否改变选型/成本/风险，是否可查，有何信息增量？优先重要且有收益的缺口。
3. 主动查同任务替代方案、原始测试条件、负面证据、独立复现与有方法的社区研究。独立性按原始数据/作者判断，转载不是交叉验证。
4. 对关键断言读取支持段落或代码位置。数字核对指标、单位、数据集、样本、日期、模型/软件版本和不确定性。
5. 回填证据台账；冲突先排查时间、版本、定义和实验条件，无法消除则并列说明。

宿主仅允许技术一手来源时，社区项目自己的实验方法与结果可作为其报告的一手证据；二手结论仅作线索，再找原始依据。

网络受限或预算不足时记录未覆盖项。核心问题有证据、带限制的假设或明确未知，关键版本已厘清，继续搜索收益下降，即可写作；不固定搜索次数、来源数、字数或页数。

## 深挖完成信号

读者能解释典型输入如何得到输出、关键实现选择为何影响结果、合理替代方案何时更合适、哪些结论不能确定。关键机制仍说不清时定向补查，不用加长概述代替研究。

BM25 的词频饱和、长度归一化、计算例子与分词影响比模型参数量重要；LangGraph 的 State、checkpoint、恢复与副作用比神经网络训练重要。JEV 等闭源模型的架构和规模可研究，但只能报告实际披露或有条件的推断。
