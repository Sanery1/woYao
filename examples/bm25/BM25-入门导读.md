## 先确定我们要解决什么

你搜索“苹果 手机”。系统找到了一批内容，但屏幕只能先展示其中几篇，应该让谁排前面？

本篇用三篇极短的内容，完整走一遍：**把文字变成词 → 数词 → 给词确定权重 → 算每篇的分数 → 按分数排序。**

BM25 负责这里的评分。完整搜索系统还会有过滤、展示等步骤，本例只把评分所需的输入准备好，再看它怎样输出排序。

## 第一步：准备词，并数出 TF

假设文字已经被切成下面这些词。这个切分过程叫**分词**；本例直接给出切分结果，不需要先学习中文分词算法。

查询被切为两个词：`苹果`、`手机`。

| 文档 | 已切好的词 |
| --- | --- |
| 甲 | 苹果、手机、手机、推荐 |
| 乙 | 苹果、苹果、苹果、推荐 |
| 丙 | 苹果、手机、价格、推荐 |

**TF（Term Frequency，词频）在本例中，就是某个词在某一篇文档里出现了几次。**

例如，甲中“手机”出现两次，所以 `TF(手机, 甲)=2`。乙没有“手机”，所以 `TF(手机, 乙)=0`。数完就得到：

| 文档 | “苹果”的 TF | “手机”的 TF | 文档长度：词的总数 |
| --- | ---: | ---: | ---: |
| 甲 | 1 | 2 | 4 |
| 乙 | 3 | 0 | 4 |
| 丙 | 1 | 1 | 4 |

这里的长度包含“推荐”“价格”等所有词，不只数查询词。这些数据就是评分的原料。

本例允许只含一个查询词的文档参与比较，所以乙也进入评分。若搜索设置要求两个词都出现，乙会在评分前被排除；这是匹配条件的选择。

## 第二步：从 TF 区分出 DF，再算 IDF

有了次数，还要知道：**命中哪个词，更能区分这批文档？**

“苹果”三篇都有，命中它很难区分三篇；“手机”只在甲和丙中出现，命中它更能缩小范围。

这里需要另一个计数：**DF（Document Frequency，文档频率），表示这批文档中，有多少篇包含某个词。**

乙写了三次“苹果”，它只算一篇包含“苹果”的文档。因此：

| 查询词 | 包含它的文档 | DF |
| --- | --- | ---: |
| 苹果 | 甲、乙、丙 | 3 |
| 手机 | 甲、丙 | 2 |

先分清这两个问题：

- TF：这个词在**这一篇里出现几次**？
- DF：**有几篇**出现过这个词？

BM25 再把 DF 转成一个权重，称为 **IDF（Inverse Document Frequency，逆文档频率）**。同一批文档中，DF 越小，下面这个版本算出的 IDF 越大；这个名称对应的就是“少见的词具有更大区分权重”。

本篇采用的具体公式是：

$$
\operatorname{IDF}(词)=\ln\left(1+\frac{N-\operatorname{DF}(词)+0.5}{\operatorname{DF}(词)+0.5}\right)
$$

其中 `N` 是文档总数，此处为 3；`ln` 是自然对数，可以用计算器计算。先把它当作把计数变为权重的既定规则，不需要先学它的理论推导。

代入本例：

- 苹果：`ln(1 + (3 − 3 + 0.5) / (3 + 0.5)) ≈ 0.133531`。
- 手机：`ln(1 + (3 − 2 + 0.5) / (2 + 0.5)) ≈ 0.470004`。

到这里，“手机”权重更大就有了确切数值。它是统计上的区分度，罕见拼写错误也可能获得高权重，不能把 IDF 当成真实语义重要性。

## 第三步：把 TF 变成贡献，先交代长度怎样参与

可以直接把 TF 乘 IDF 吗？那样乙只要不断重复“苹果”，分数就能一直按相同比例增长。

BM25 会先调整 TF：重复仍有收益，但增加到后面，每多一次的收益会变小。这个效果叫**词频饱和**。它还会结合篇幅，区分“短文出现两次”和“长文出现两次”。

为了把这两件事算清楚，先准备长度数据：

- 当前文档的长度记为 `L`。
- 全部文档的平均长度记为 `平均L`，本例是 `(4+4+4)/3=4`。
- `k1` 控制词频饱和的形状，本篇固定为 1.2。
- `b` 控制长度调整的强弱，本篇固定为 0.75。它们是本次计算选定的参数，不是从这三篇短文训练出来的。

先算长度调整量 `K`：

$$
K=k_1\left(1-b+b\frac{L}{平均L}\right)
$$

现在三篇长度都等于平均长度，所以每篇都是：

`K = 1.2 × (1 − 0.75 + 0.75 × 4/4) = 1.2`。

然后用 TF 算出词频贡献因子，记为 `A`：

$$
A=\frac{\operatorname{TF}(k_1+1)}{\operatorname{TF}+K}
$$

在本例中，它化为 `A = TF × 2.2 / (TF + 1.2)`：

| TF | 代入计算 | A |
| ---: | --- | ---: |
| 0 | 0 × 2.2 / 1.2 | 0 |
| 1 | 1 × 2.2 / 2.2 | 1 |
| 2 | 2 × 2.2 / 3.2 | 1.375 |
| 3 | 3 × 2.2 / 4.2 | 1.571429 |

**TF 是原始次数，A 是处理后的贡献因子，两者不能混叫。** TF 从 1 到 2 增加一次，A 增加 0.375；TF 从 2 到 3 同样增加一次，A 只再增加约 0.196。这就是刚才说的“词频饱和”。

## 第四步：乘权重，再汇成每篇的总分

现在所有原料都有了：IDF 表示词的区分权重，A 包含这篇文档的 TF 与长度影响。

**一个查询词的贡献 = IDF × A；一篇文档的得分 = 各个查询词的贡献之和。**

先完整算甲：

1. “苹果”TF=1，所以 A=1，贡献 `0.133531 × 1 = 0.133531`。
2. “手机”TF=2，所以 A=1.375，贡献 `0.470004 × 1.375 ≈ 0.646255`。
3. 两项相加，甲的得分 `0.133531 + 0.646255 ≈ 0.779786`。

按相同步骤算乙和丙：

| 文档 | “苹果”的贡献 | “手机”的贡献 | 总分 |
| --- | ---: | ---: | ---: |
| 甲 | 0.133531 × 1 ≈ 0.133531 | 0.470004 × 1.375 ≈ 0.646255 | 0.779786 |
| 乙 | 0.133531 × 1.571429 ≈ 0.209835 | 没出现，贡献 0 | 0.209835 |
| 丙 | 0.133531 × 1 ≈ 0.133531 | 0.470004 × 1 ≈ 0.470004 | 0.603535 |

展示的中间数已四舍五入，最终值按完整精度计算。

## 第五步：排序，回答最开始的问题

把总分从高到低排，得到：**甲 → 丙 → 乙**。

为什么甲第一？它和丙都出现了两个查询词；长度相同时，甲多出现一次“手机”，这个词多贡献了一些分数。

为什么乙最后？它虽然重复三次“苹果”，却缺少权重更大的“手机”；“苹果”的重复收益还经过了饱和处理。在这个具体例子里，这些线索合起来让乙得分更低。

我们现在已经从给定的文字和切词结果，数出了 TF、DF，计算 IDF、K、A，得到各词贡献与总分，并回答了“先展示哪篇”。这些步骤就构成了本例的完整评分过程。

这不表示“含两个词永远胜过只含一个词”，也不表示 0.78 是 78% 正确率；换输入和条件，评分也会变。

## 再改一个条件，看看长度调整是否真的起作用

刚才长度都相同，所以长度调整没有拉开差距。现在只在乙末尾加四个词：

`苹果、苹果、苹果、推荐、评测、使用、体验、分享`。

乙的查询词 TF 没变，两个查询词的 DF 也没变，所以 IDF 不变。但是乙的长度变成 8，平均长度变成 `(4+8+4)/3 = 16/3`。

重新代入第三步的公式：

- 甲、丙：`K = 1.2 × (0.25 + 0.75 × 4/(16/3)) = 0.975`。
- 乙：`K = 1.2 × (0.25 + 0.75 × 8/(16/3)) = 1.65`。

乙的“苹果”贡献现在是：

`0.133531 × (3 × 2.2 / (3 + 1.65)) ≈ 0.189528`。

“手机”仍贡献 0，所以乙从约 0.209835 降到了 0.189528：重复次数相同，篇幅增加了，它的词频贡献就被调低。

按同一规则重算三篇：

| 文档 | 新的“苹果”贡献 | 新的“手机”贡献 | 新总分 |
| --- | ---: | ---: | ---: |
| 甲 | 0.148744 | 0.695131 | 0.843875 |
| 乙 | 0.189528 | 0 | 0.189528 |
| 丙 | 0.148744 | 0.523548 | 0.672292 |

甲和丙没有改字，分数也变了，因为整批内容的平均长度变了。这个例子说明：**文档分数既依赖它自己的词和长度，也依赖整批文档的统计。** 本次排序仍是甲、丙、乙。

## oOO!

TF 数一篇里出现几次，DF 数有几篇出现过；IDF 把 DF 变为区分权重；BM25 再把 TF 经饱和与长度调整，乘上权重，并把各词贡献相加。分数排出顺序，才回答了搜索最初的问题。
