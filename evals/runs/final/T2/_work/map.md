# 学习目标题

### G1〔为什么〕模型给出 quote 请求后，为什么宿主还需要执行、保存 assistant 消息和回传 tool 消息，再请求模型？
- 负责节：§1–2
- 答案要点：
  - 模型仅提出结构化请求，实际函数执行由宿主负责。
  - 保存原 assistant 请求，使 tool_call_id 有对应的调用身份。
  - 将结果加入历史再次请求，模型才可据结果生成最终回答。

### G2〔为什么〕已经向模型提供工具 schema，为什么 Python 还要检查名字、字段和类型？
- 负责节：§4
- 答案要点：
  - schema 表达预期但兼容服务可能不严格遵循，外部参数仍须验证。
  - 名字白名单约束执行能力，禁止任意 eval/导入。
  - JSON对象、字段集合、整数及范围需要实际验证，bool不能充当金额整数。

### G3〔迁移/判断〕把报价工具换成下单工具，网络超时后能否照常自动重试？持续工具请求又该怎样停止？
- 负责节：§6
- 答案要点：
  - 超时不能证明远端没有执行，下单重试可能重复产生副作用。
  - 写操作需业务幂等身份/查询或人工决策，本实现没有提供该保证。
  - 循环以模型请求次数上限停止并报预算耗尽，不能伪造成功。

### G4〔实现〕如何配置兼容接口，并正确处理单轮两个工具请求与最终文本？
- 负责节：§2–4
- 答案要点：
  - base追加/chat/completions，model为provider标识，密钥来自环境；兼容性需确认。
  - arguments字符串需JSON解析，每个请求分别执行并按各自tool_call_id回传。
  - 无工具请求时还需检查正常结束与完整文本，截断不能当成功。

### G5〔验证〕本次 mock HTTP 验证哪些路径，为什么还不能证明真实 provider 的最终答案正确？
- 负责节：§5–7
- 答案要点：
  - 观察计算结果3897及第二次请求的消息关联，并覆盖多调用、错误、预算与协议失败。
  - mock脚本不理解语义，成功只支持宿主协议实现的列明分支。
  - 真实provider字段支持、模型调用选择与答案准确性仍待实测。
