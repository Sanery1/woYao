# T3 写作前固定目标

固定时间：2026-11-25；woYao 0.19.0-preview.5。读者会后端，理解原理，完整篇幅，只要 Markdown。

1. 从一次报价审批工作流的进程崩溃追踪恢复，区分业务状态、控制位置和外部副作用。
2. 解释 checkpoint、持久化提交、调度/重试与 replay 的因果关系，并能推导崩溃窗口。
3. 解释 LangGraph 的 thread、状态快照、super-step、pending writes、恢复入口与耐久模式的边界。
4. 解释 Temporal 的事件历史、Workflow 重放、Activity 重试与确定性契约，并与 LangGraph 作机制对照。
5. 基于幂等、未知结果、人审、并发和代码升级分析取舍，设计能验证恢复语义的故障注入方案。

## 研究问题地图

核心：恢复数据的最小闭包；保存和执行的先后关系；外部效果与记录之间的原子性缺口；快照与历史的区别。
先修：本地事务、进程内存与持久存储、网络超时无法证明对端未执行、状态机。
深入：至少一次与业务幂等、稳定标识、并行汇合、版本与确定性、异步刷盘恢复窗口、恢复和重新输入的差异。
延伸不做：集群安装教程、跨云容量压测、未经运行的性能数字、把框架承诺等同业务恰好一次。
