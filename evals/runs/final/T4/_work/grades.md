# T4 独立评分

评分来源仅为 grading-packet.json 中本主题的题干、预先固定金标及双轮读者对应题回答与直接引文。未读取报告或其他评分，未从主线复述补分。

规则：2 分为全部固定要点；1 分为至少一半要点（奇数项向上取整）；0 分为其余或整题明确“报告未说明”。部分答出、部分未说明时按实际命中评分；等效表述接受，未完整表达的复合要点计为缺失。

两轮总分：第 1 轮 8/10；第 2 轮 7/10。均分：7.5/10。

## 第 1 轮：8/10

### 第 1 题：1/2

题干：模型每生成一个新的字（token），为什么都要"回看"前面所有的内容？

命中：模型通过注意力机制决定下一个 token

缺失：在普通因果全注意力模型中，当前 query 和可见前文的 key 计算关联；滑动窗口等结构例外

对应答案/直接引文：

> 注意力会判断当前这个位置该从历史哪些位置取信息……没有说每个历史位置都同样重要。

报告缺口（仅按该题回答可确认）：未在本题答案/直接引文表达当前 Q 对可见 K 的关联计算及普通因果全注意力的范围/滑动窗口例外。

### 第 2 题：1/2

题干：如果不用 KV cache，会多做什么重复工作？

命中：每生成一个 token，都要重新计算前面所有 token 的中间结果（K、V）

缺失：文本越长，重复计算越多

对应答案/直接引文：

> 下一步还要重新产生前面历史位置已经算过的 K 和 V。

报告缺口（仅按该题回答可确认）：未直接说明文本越长，重复计算越多；不能从主线或其他题补足。

### 第 3 题：2/2

题干：KV cache 存的是什么？为什么不需要缓存 Q？

命中：存的是已处理 token 在每一层的 K 和 V；Q 只在计算当前这个新 token 时用一次，之后不再需要

缺失：无。

对应答案/直接引文：

> 保存每层历史位置的 K 和 V……下一步用当前 token 的 Q……旧 Q 没有在这个流程里再用到。

报告缺口（仅按该题回答可确认）：虽由流程推导，答案已正确表达旧 Q 不再复用，接受等效表述。

### 第 4 题：2/2

题干：KV cache 占用的显存随什么增长？

命中：随上下文长度（token 数）大致线性增长；随同时服务的请求数增长；和模型的层数、规模有关

缺失：无。

对应答案/直接引文：

> 所有活跃请求保留的 token 总数……层数、KV 通道数……公式 2 × L × H × D × S × T。

报告缺口（仅按该题回答可确认）：公式直接支持线性关系；本题无缺口。

### 第 5 题：2/2

题干：同一张显卡，为什么对话越长、同时在线的人越多，就越容易显存不够？有哪些缓解思路？

命中：KV cache 总量 ≈ 每个请求的长度 × 请求数，会把显存占满；至少说出两种缓解办法：减少 KV 头数（GQA/MQA）、KV 量化、分页管理（PagedAttention）、限制上下文长度或使用滑动窗口

缺失：无。

对应答案/直接引文：

> 不同活跃请求一般各存自己的上下文缓存；长对话和更多请求……控制回答长度……分页……KV 量化。

报告缺口（仅按该题回答可确认）：本题无可据回答确认的缺口。
