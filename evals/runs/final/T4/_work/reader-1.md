# T4 独立模拟读者第 1 轮

读者档位：A（不写代码的产品人员）。仅依据题干及 `reader-copy.md` 回答。

副本 SHA256：`BC7500B7F146BE4EDDD556F19CFD53F4396DBB40AF5C9BB3EE1BEA8DC9E55647`

## 主线复述

模型逐 token 生成，每一步会根据已有文本寻找当前需要的信息。
KV cache 把历史内容已经算出的匹配线索与内容数字留下，下一步复用它们。
缓存省去重复计算历史 KV，但历史读取和注意力工作仍在。
会话越长、同时活跃请求越多，需要保存的缓存越大，模型放得下不代表会话也放得下。
优化要分清分页、前缀复用、降低精度或迁移存放的位置，并用质量和延迟约束下的实际成本验收。

## 逐题回答

### 1. 每生成一个 token 为什么要回看前面内容？

原回答：因为模型要根据已有内容预测接下来的内容，才能把回答接着写下去。注意力会判断当前这个位置该从历史哪些位置取信息，比如回答保修问题时仍可能需要参考前面手册中的信息；报告并没有说每个历史位置都同样重要。

支持：§1“依据已有文本预测下一个token，再把新结果接回上下文继续预测”；“注意力负责判断当前位置应该从哪些历史位置取信息”。

### 2. 没有 KV cache 多做什么重复工作？

原回答：下一步还要重新产生前面历史位置已经算过的 K 和 V。缓存让旧结果可以直接拿来用，只增加新位置所需的计算；它没有省掉对历史的读取和当前注意力匹配。

支持：§1“缓存省下的是反复生成历史K、V的工作；对历史的读取和注意力计算仍然存在”。

### 3. 缓存存什么，为什么不缓存 Q？

原回答：它保存每层历史位置的 K 和 V，两者都是数字；K 是供当前问题匹配的线索，V 是随后汇集的内容，不是文字摘要。按报告的解释，下一步用当前 token 的 Q 去匹配历史 K、汇集历史 V，所以能复用的是旧 K/V，旧 Q 没有在这个流程里再用到。“为什么不需要缓存 Q”没有独立小节，这一部分是我按该流程的理解。

支持：§1“当前token产生Q……每个可见位置产生K……以及V”；“当前Q仍然要与历史K匹配，再汇集相应V”。

### 4. 缓存显存随什么增长？

原回答：在模型和缓存存储方式固定时，随所有活跃请求保留的 token 总数增长，既包括输入，也包括已经生成的回答。每条对话变长或活跃请求变多都会增加；此外层数、KV 通道数、每个通道的数字个数、每个数字用多少字节，也决定每 token 的大小。

支持：§2“总缓存token数T是所有活跃请求实际保留长度之和”；公式 `2 × L × H × D × S × T`；§3 长度和并发同时翻倍，缓存四倍。

### 5. 长对话、多用户为什么更容易显存不足，有何缓解？

原回答：权重通常共享，但不同活跃请求一般各存自己的上下文缓存；长对话和更多请求会一起挤占这笔预算，还得留出运行时空间。可以先减少无关输入、控制回答长度和活跃并发，再按原因评估分页减少分配浪费、相同前缀复用、KV 量化，或把缓存迁到 CPU 等位置。选择时要同时测试质量、首字等待、后续生成速度和峰值显存，不能只凭命中率承诺省钱。

支持：§2“新增用户未必复制一份权重，却会新增其会话状态”；§3 长度与并发；§4 三种优化及 CPU 迁移；§5 验收指标。

## 卡点

- Q 不缓存的原因需要从“当前 Q 对历史 K/V”的描述推出来，报告没有直接一句话收束。
- 缓存容量的算术容易理解，但不能仅凭它知道真实设备能服务多少人，仍需工程压测，报告也保留了这个界限。
